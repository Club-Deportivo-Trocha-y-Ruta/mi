# Design: Invitation-Based Onboarding Flow

**Date:** 2026-04-15
**Based on:** `docs/08-onboarding/research.md`
**Prerequisite:** `docs/06-parents/workflow.md` (parents module already implemented)

---

## 1. General Overview

### Problem
The invitation backend is complete, but the frontend has a flat registration page (`ParentRegisterPage`) that does not include parental consent, is not multi-step, and has a route mismatch with the URL generated by the backend (`/onboarding` vs `/registro-padre`).

### Solution
Convert the flow into a **multi-step wizard at `/onboarding`** that:
1. Validates token → infers role → shows role-specific steps
2. Includes mandatory parental consent for parents
3. Is extensible for coaches (Phase 1B) and athletes (Phase 2+)

### Scope by Phase

| Phase | Roles | Deliverables |
|---|---|---|
| **1A (this sprint)** | Parent/Guardian | 4-step wizard, consent, email template |
| **1B (next sprint)** | Coach | "Professional profile" step + accept club terms |
| **2+** | Athlete (>16 years) | Sports profile + own consent |

#### 2.2.3 New `ParentalConsent` model

```python
# backend/app/models/parental_consent.py
class ParentalConsent(Base):
    __tablename__ = "parental_consents"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    parent_user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    athlete_id: Mapped[int] = mapped_column(ForeignKey("athletes.id"))
    consent_version: Mapped[str] = mapped_column(String(20))  # "v1.0"
    consented_at: Mapped[datetime] = mapped_column(DateTime)
    consent_method: Mapped[str] = mapped_column(String(50), default="digital_wizard")
    ip_address: Mapped[str | None] = mapped_column(String(45), nullable=True)
    data_collection: Mapped[bool] = mapped_column(Boolean, default=False)
    training_tracking: Mapped[bool] = mapped_column(Boolean, default=False)
    anthropometry: Mapped[bool] = mapped_column(Boolean, default=False)
    third_party_sharing: Mapped[bool] = mapped_column(Boolean, default=False)
    withdrawn_at: Mapped[datetime | None] = mapped_column(DateTime, nullable=True)

    parent: Mapped["User"] = relationship("User")
    athlete: Mapped["Athlete"] = relationship("Athlete")
```

#### 2.3.4 Zod schemas per step

```typescript
// frontend/src/schemas/onboarding.schema.ts

export const accountSchema = z
  .object({
    password: z
      .string()
      .min(8, "Minimum 8 characters")
      .regex(/[A-Z]/, "Must contain at least one uppercase letter")
      .regex(/[0-9]/, "Must contain at least one number"),
    password_confirm: z.string(),
  })
  .refine((d) => d.password === d.password_confirm, {
    message: "Passwords do not match",
    path: ["password_confirm"],
  });

export const parentProfileSchema = z.object({
  first_name: z.string().min(1, "First name is required").trim(),
  last_name: z.string().min(1, "Last name is required").trim(),
  phone: z
    .string()
    .regex(/^\+?[0-9]{7,13}$/, "Invalid phone number")
    .optional()
    .or(z.literal("")),
  relationship_type: z.enum(["padre", "madre", "acudiente"], {
    required_error: "Select the relationship",
  }),
});

export const consentSchema = z.object({
  accept_data_collection: z.literal(true, {
    errorMap: () => ({
      message: "You must authorize data collection to continue",
    }),
  }),
  accept_training_tracking: z.literal(true, {
    errorMap: () => ({
      message: "You must authorize sports tracking to continue",
    }),
  }),
  accept_anthropometry: z.literal(true, {
    errorMap: () => ({
      message: "You must authorize anthropometric measurements to continue",
    }),
  }),
  accept_third_party: z.boolean().default(false), // optional
});

// Combined schema for full form type-safety
export const onboardingFormSchema = accountSchema
  .and(parentProfileSchema)
  .and(consentSchema);

export type OnboardingFormData = z.infer<typeof onboardingFormSchema>;
```

#### 2.3.5 Zustand Store

```typescript
// frontend/src/stores/onboarding-store.ts
import { create } from "zustand";
import { persist } from "zustand/middleware";

interface OnboardingState {
  currentStep: number;
  role: "parent" | "coach" | "athlete" | null;
  token: string | null;
  email: string | null;
  athleteName: string | null;
  clubName: string | null;
  formData: Record<string, unknown>;
  setStep: (step: number) => void;
  setTokenData: (data: {
    role: string;
    token: string;
    email: string;
    athleteName: string;
    clubName: string;
  }) => void;
  updateFormData: (data: Record<string, unknown>) => void;
  reset: () => void;
}

export const useOnboardingStore = create<OnboardingState>()(
  persist(
    (set) => ({
      currentStep: 0,
      role: null,
      token: null,
      email: null,
      athleteName: null,
      clubName: null,
      formData: {},
      setStep: (step) => set({ currentStep: step }),
      setTokenData: ({ role, token, email, athleteName, clubName }) =>
        set({ role: role as any, token, email, athleteName, clubName }),
      updateFormData: (data) =>
        set((s) => ({ formData: { ...s.formData, ...data } })),
      reset: () =>
        set({
          currentStep: 0,
          role: null,
          token: null,
          email: null,
          athleteName: null,
          clubName: null,
          formData: {},
        }),
    }),
    {
      name: "trocha-onboarding",
      // Clear if token expired (72h since storage)
    }
  )
);
```

## 4. Data Models — Changes

### New table: `parental_consents`

| Column | Type | Constraint | Description |
|---|---|---|---|
| `id` | INT | PK, AUTO | — |
| `parent_user_id` | INT | FK users.id, NOT NULL | Parent granting consent |
| `athlete_id` | INT | FK athletes.id, NOT NULL | Minor athlete |
| `consent_version` | VARCHAR(20) | NOT NULL | Policy version ("v1.0") |
| `consented_at` | DATETIME | NOT NULL | UTC timestamp |
| `consent_method` | VARCHAR(50) | NOT NULL, DEFAULT "digital_wizard" | Verification method |
| `ip_address` | VARCHAR(45) | NULLABLE | Parent's IP when accepting |
| `data_collection` | BOOLEAN | NOT NULL, DEFAULT FALSE | Personal data collection |
| `training_tracking` | BOOLEAN | NOT NULL, DEFAULT FALSE | Sports tracking |
| `anthropometry` | BOOLEAN | NOT NULL, DEFAULT FALSE | Anthropometric measurements |
| `third_party_sharing` | BOOLEAN | NOT NULL, DEFAULT FALSE | Share with third parties |
| `withdrawn_at` | DATETIME | NULLABLE | Revocation date (NULL = active) |

**Indexes:**
- `(parent_user_id, athlete_id)` — fast lookup for active consent
- `athlete_id` — lookup by athlete

### Existing tables — no structural changes

- `parent_invites` → no changes (raw token kept for now; hashing is a Phase 1B improvement)
- `athletes` → `parental_consent_obtained` and `parental_consent_date` already exist, updated in `consume_invite()`
- `users`, `club_members`, `parent_athlete` → no changes

## 8. Security Considerations

| Area | Measure | Priority |
|---|---|---|
| Token in URL | Already uses `token_urlsafe(32)` — secure | ✅ OK |
| Token in DB | Raw currently. Hash with SHA-256 in Phase 1B | 🟡 Medium |
| CSRF | Public POST endpoint — protect with already-configured CORS | ✅ OK |
| Rate limiting | Not implemented. Add in Phase 1B (slowapi + Redis) | 🟡 Medium |
| XSS | React escapes by default. Email template uses Jinja2 autoescaping | ✅ OK |
| Minors' data | Do not expose in logs/commits. Privacy hook active | ✅ OK |
| Consent | Recorded with IP + timestamp + policy version | ✅ New |

## 10. Architectural Decisions

| Decision | Discarded alternative | Reason |
|---|---|---|
| Multi-step wizard | Single long form | Progressive UX, granular validation, extensible by role |
| Zustand persist | Context API | localStorage persistence, progress recovery |
| Custom stepper | SmartStepper npm | Full control over UX, native integration with shadcn |
