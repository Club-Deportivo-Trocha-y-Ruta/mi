# Quickstart — validating feature 043 (race course profile)

**Feature**: `specs/043-race-course-profile/` · **Branch**: `feat/043-race-course-profile`

Validation guide only. Field names, limits and algorithms are fixed in [`spec.md`](spec.md), [`data-model.md`](data-model.md) and [`contracts/`](contracts/); nothing is re-derived here. Same three transcript rules as feature 042: **no secrets** (refer to `MYSQL_PASS`, `RACE_AI_API_KEY`, `TEST_DATABASE_URL` by name only), **no minor's data** (synthetic fixtures and the seeded demo válida only), and **no real recording in the repository** — every GPX used below is generated by `backend/tests/helpers/gpx_builder.py` or lives in `frontend/e2e/fixtures/` as a synthetic file; never commit a coach's actual ride.

---

## 1. Prerequisites

```bash
cd backend && source .venv/bin/activate        # invoke pytest as .venv/bin/python -m pytest
alembic upgrade head                            # needs MySQL up (docker compose up mysql) — applies the 043 revision
cd ../frontend && npm ci
```

`alembic heads` must print exactly one head (the 043 revision, `down_revision=d5b125474e2b`).

## 2. Backend — default lane (offline, aiosqlite)

```bash
cd backend
.venv/bin/python -m pytest tests/services/race/test_gpx_processing.py -q     # contracts/gpx-processing.md §4
.venv/bin/python -m pytest tests/routers/test_race_course.py -q              # contracts/course-api.md §7
.venv/bin/python -m pytest tests/services/race/test_results_derived.py -q    # contracts/results-derived-figures.md §4
.venv/bin/python -m pytest tests/services/race/ai -q -k course               # contracts/ai-course-block.md §5
.venv/bin/python -m pytest -q                                                # whole suite still green
ruff check
```

Expected: all green; the privacy tests prove that a GPX with `<time>`, Garmin extensions and `<metadata><author>` produces a row and a response with none of those strings, and that `caplog` holds no filename or coordinate.

## 3. Backend — MySQL lane and migration round-trip

```bash
# TEST_DATABASE_URL=mysql+aiomysql://…/<name>_test  (name must end in _test)
.venv/bin/python -m pytest -m mysql -q -k "course or race_event"
alembic downgrade -1 && alembic upgrade head            # against the local docker MySQL
```

Expected: JSON `geometry` round-trips; `terraintype` enum exists after upgrade and is gone after downgrade; the `RESTRICT` FK on `variant_id` blocks deletion at the database level (the API returns 409 before reaching it).

## 4. Golden evaluation (opt-in, needs `RACE_AI_API_KEY`)

```bash
.venv/bin/python -m pytest -m golden tests/evals/test_race_analyst_eval.py -q
```

Expected: composite ≥ 0.75 with the two new cases (`course_present`, `course_absent`); the absent case fails if the text mentions km, vueltas, terreno, desnivel or dificultad. Update `baseline_*.json` per the existing procedure in `docs/10-race-results/runbook-ops.md`.

Expected: zero jest-axe violations on `CourseTab`, the two sheets, `CourseSummary`, the parents page and the detail page on `?tab=circuito`; results columns rendered only with `has_course_data`.

## 6. Manual walk-through (docker compose stack, coach account from the demo seed)

1. Open a válida → tab **Circuito** → "Agregar variante" → upload `frontend/e2e/fixtures/course_3laps.gpx` as "Circuito completo". Expect the confirmation "Detectamos 3 vueltas de 4,0 km …". Save.
2. Upload `course_reduced.gpx` as "Recorrido reducido" (single lap, expect "single" copy with no question).
3. Setups table: set 3 laps / Circuito completo for two categories and 2 laps / Recorrido reducido for one; save. Reload: persisted.
4. Description: terrain "mixto", difficulty 4, two sectors, 300-char notes; save; card shows complete state.
5. Tab **Resultados**: columns "Distancia" and "Vel. prom." visible; a `minus_laps` row without `laps_behind` shows "sin dato".
6. Create a **second** válida in the same series (higher sequence number) → tab Circuito → setups table shows the banner "Sugerido desde la válida anterior" with the same laps; confirm.
7. Delete "Recorrido reducido" while referenced → toast names the category; clear that setup, delete again → gone.
8. Import wizard for a new válida → commit → step 3 shows "Circuito (opcional)" with the same upload flow.
9. Log in as the seeded parent whose child is on the roster → competition page shows the course card with the child's category laps; a parent without a registered child sees no card (network tab: 404, no toast).
10. With a real AI provider configured locally, run the per-válida analysis for a rider in the válida with course data: the insight may mention distance/terrain; run it for a válida without course data: it must not. Verify in the Langfuse trace (local only) that no notes text appears anywhere.

Timing for SC-001: steps 1, 3 and 4 together on a tablet should take under 5 minutes.

Runs against the isolated Playwright stack (`docker-compose.e2e.yml`, fake AI provider). Requires `VITE_API_BASE_URL` set per the note in `playwright.config.ts`.
