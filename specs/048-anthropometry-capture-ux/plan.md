# Implementation Plan: Guided anthropometric capture (weight, standing height, sitting height, arm span)

**Branch**: `main` (owner decision: no dedicated branch, no auto-commits) | **Date**: 2026-09-29 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/048-anthropometry-capture-ux/spec.md`

## Summary

The basic anthropometric evaluation becomes a guided, online-only capture with a quick mode.

- **Guided mode** runs pre-check → one illustrated step per measure (single reading, bench subtraction for sitting height) → review. The review shows server-computed plausibility warnings and a plain-language PHV summary, and keeps the two 046 save exits.
- **Correction**: records become editable and deletable by their evaluator or an admin. Derived values are recomputed through a derivation service extracted from the POST handler. Every edit and delete is audited, and edits invalidate the stored AI explanations.
- **Group session**: an in-memory queue over a new batch roster endpoint.
- **Field guide**: the printable guide gains the basic measures from a single JSON text source.

There is **no migration**: duplicates are prevented by a same-date rule, the "Revisar" marker is derived at read time, and edits never notify.

Illustrations are generated by the orchestrating session in the owner's Chrome session (Gemini/ChatGPT web), and the owner approves each one. E2E runs locally on the isolated stack.

## Technical Context

**Language/Version**: Python 3.13 (backend), TypeScript / React 19 (frontend)

**Primary Dependencies**:
- **Backend**: FastAPI, SQLAlchemy 2 async, Pydantic v2, WeasyPrint (field guide). No new dependencies.
- **Frontend**: TanStack Query, React Hook Form + Zod, Zustand, shadcn/ui + Tailwind v4. No new dependencies.

**Storage**: MySQL 8.4 in production and aiosqlite in tests. There are **no schema changes** (see data-model.md). New static assets:
- `frontend/src/assets/anthropometry/*.webp`
- `backend/templates/documents/pdf/diagrams/img/anthro_*.png`
- `backend/app/data/anthropometry_measures.json`

**Testing**:
- **Backend**: pytest + `httpx.AsyncClient`, in a new package `backend/tests/anthropometry/`.
- **Frontend**: vitest + Testing Library + MSW + jest-axe.
- **E2E**: Playwright, run **locally on the isolated stack** (owner request; research R12), including 360 px variants.

**Target Platform**: Render (API) and the Hostinger SPA. The primary device is the coach's tablet at the venue; the phone is secondary.

**Project Type**: Web application (backend + frontend).

**Performance Goals**:
- API p95 ≤ 500 ms.
- The roster uses ≤ 4 queries for a 40-athlete club.
- The plausibility dry-run loads only the previous record.
- New routes are lazy-loaded, each ≤ 150 KB gzip. The four webp files are about 40–60 KB each, loaded only on the capture route.

**Constraints**:
- Online-only capture (clarification 1).
- One reading per measure (clarification 2).
- Edit and delete only by the evaluator or an admin (clarification 3).
- The marker is derived, never stored (clarification 4).
- No athlete data in image prompts, logs, audit values or errors (Ley 1581).

**Scale/Scope**:
- One club, 20–40 athletes, 3–4 measurement days a year.
- 3 new pages, 4 new endpoints and 2 changed endpoints.
