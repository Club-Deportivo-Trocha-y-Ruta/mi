# Phase 1 Data Model: Improve Individual Monthly Newsletter

**Feature**: `003-improve-individual-newsletter-pdf` | **Date**: 2026-06-05

This feature is **mostly behavioral** (rendering, pagination, content generation). It introduces **no new tables or columns**. It changes how two existing tables are *populated* and adds optional, non-persisted shape to the newsletter context blocks.

---

## E1 — `growth_reference_lms` (existing table — populate, no schema change)

CDC L-M-S reference constants used to compute z-scores/percentiles. Source: `app/models/growth.py` (`GrowthReferenceLms`).

| Field | Type | Notes |
|---|---|---|
| `source` | enum(`CDC`,`WHO`) | seeded with `CDC` |
| `indicator` | enum(`height_for_age`,`bmi_for_age`,`weight_for_age`) | three CDC datasets |
| `sex` | enum(`M`,`F`) | |
| `age_months` | DECIMAL(5,1) | 24.0–240.5 (CDC valid range) |
| `L`,`M`,`S` | DECIMAL | reference constants (no minor data) |

**Change:** Populate this table deterministically in all environments via **vendored CDC CSVs** committed to the repo (not a live `cdc.gov` download), loaded by an **idempotent** seeding step (respects `uq_lms_source_indicator_sex_age`). No row contains athlete data.

**Validation:** After seeding, each `(source, indicator, sex)` group MUST cover the full 24–240.5-month range; a coverage check asserts non-empty groups for all six (3 indicators × 2 sexes).

## E2 — `anthropometric_records` (existing table — populate values, no schema change)

Source: `app/models/anthropometry.py`. The relevant nullable derived columns already exist (`:74–81`): `bmi`, `height_z_score`, `height_percentile`, `bmi_z_score`, `bmi_percentile`, `weight_z_score`, `weight_percentile`, `nutritional_status`.

**State transition — on capture (`routers/anthropometry.create_anthropometry`):**

```
raw measurements (weight, height, sitting_height, dob, sex)
   │
   ├─ PHV (Mirwald)  → maturity_offset, age_at_phv, maturation_status   [already populated]
   ├─ BMI            → bmi = weight_kg / (height_m**2)   [NEW: always, even if LMS missing]
   └─ LMS lookup     → height/bmi/weight z-scores + percentiles + nutritional_status
                       [now non-empty because E1 is seeded]
```

**Rules:**
- `bmi` MUST be set whenever `weight_kg` and `standing_height_cm` are present, regardless of LMS availability. (Fixes the coupling bug where `bmi=None` when `growth is None`.)
- Percentile/z-score fields are set when the LMS group covers the athlete's age/sex; otherwise they remain `NULL` and the newsletter shows `—` **with a plain-language reason** (FR-002).
- Raw measurement columns are **never** modified by this feature.

**Backfill (one-time, idempotent):** For each record with NULL `bmi` (and/or NULL percentiles) but non-NULL raw measurements, recompute and persist using the same `services/growth.py` + BMI formula. Re-running is a no-op for already-populated rows. Reads/writes only server-side; no new exposure.

**Validation invariant (test):** After backfill, every record with `weight_kg` and `standing_height_cm` has non-NULL `bmi`; every record whose age/sex is within a seeded LMS group has non-NULL percentiles.

## E3 — Newsletter context blocks (in-memory shape — not persisted as new columns)

Produced by `services/training/newsletter_builder.build_newsletter_metrics` → `{email_blocks, pdf_only_blocks}`, stored in `AthleteMonthlyNewsletter.ai_narrative` / blocks JSON as today. New **optional** keys:

| Key | Location | Shape | Privacy |
|---|---|---|---|
| `block_captions` | per email/pdf block | `{ attendance: str, technical: str, race_results: str, anthropometry: str }` short plain-language lines | No names; guardrailed |
| `month_highlights` | top-level narrative | `str` (≤80 words) | No names; guardrailed |
| `support_at_home` | email block (existing) | `{ tips: [{category,title,text}] }` (unchanged shape; selection may be AI-adapted from a fixed library) | Static-vetted text |
| `confidence` | narrative (existing) | `low|medium|high` | unchanged |
| `unavailable_reason` | anthropometry rows | optional `str` explaining a `—` cell | No names |

**Constraints:**
- Anthropometry-derived captions/values appear **only** in `pdf_only_blocks` (never email). (FR-004)
- `block_captions` and `month_highlights` are generated by the extended `AthleteNewsletterUseCase` under existing guardrails; on missing consent / LLM failure they fall back to deterministic static strings (FR-009/FR-010).
- All new strings are español neutro (Colombia), no diagnostic/peer-ranking/discouraging language (FR-011).

## E4 — AI use case I/O (extended contract)

`AthleteNewsletterUseCase.run(ctx) -> AthleteNewsletterNarrativeOut` (`use_cases/athlete_monthly_newsletter.py:50–58`).

**Added optional output fields:** `block_captions: dict[str,str] | None`, `month_highlights: str | None`. Existing fields (`strengths`, `area_to_develop`, `milestone`, `confidence`, `model`, `prompt_version`) unchanged. Word/medical/name guardrails apply to the new fields via the existing `scrub_block` path.

No DB schema change — these serialize into the existing blocks/narrative JSON.
